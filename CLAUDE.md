# Fat Loss Coach — project guide for Claude

Native iOS port of a single-file web app (`my_fitness_coach_4.html`, localStorage) for one user's
fat-loss programme. SwiftUI, iOS 17+, iPhone only. This file is the knowledge base: read it before
touching the project.

## Data model (mirrors the old localStorage keys)

| Web key | `AppData` field |
|---|---|
| `weight-logs` / `cur-weight` | `weightLogs: [MeasurementEntry]` (one per date, last write wins) |
| `waist-logs` / `cur-waist` | `waistLogs` |
| `rec-YYYY-MM-DD` | `recovery[date]: RecoveryDay` (hrv, rhr, sleepH, deepH, remH, resp, mood) |
| `po-{Exercise}` | `overload[name]: [ExerciseLog]` (date, kg, reps) |
| `habits-YYYY-MM-DD` | `habits[date]: Set<String>` |
| `supps-YYYY-MM-DD` | `supplements[date]: Set<String>` |
| `water-YYYY-MM-DD` | `water[date]: Int` (ml) |
| `health-sync` | `health[date]: HealthDay` (steps, restingHR) |
| `ex-YYYY-MM-DD-Mon` | `exerciseDone["date-Mon"]: Set<Int>` |
| — (new) | `meals[date]: [MealEntry]` (slot = breakfast/lunch/snack/dinner/evening), `breathing[date]`, `goals`, `program` (phase + startDate) |

Dates are **local** `yyyy-MM-dd` (`DateKey`). The web app used UTC; imported dates are taken as-is.
Every struct has a lenient `init(from:)` (missing keys → defaults) so old JSON always decodes.
Storage: one JSON file `Application Support/fatloss-data.json`, saved 400 ms after any change and on
background. `AppData.merged(with:)` is a union merge used by cloud sync; scalar conflicts go to the
newer `updatedAt`, programme phase goes to the further-along one.

## Rules that were learned the hard way

- **Never mutate `Store.data` inside its own `didSet`.** Build 1 did (`data.updatedAt = Date()`),
  which re-entered the setter forever and crashed on every write. Modification time lives in
  `Store.lastModified` and is stamped into `snapshot()` only when saving/exporting/pushing.
- `@Observable` classes cannot have `lazy var`; use a computed property (see `MealScanner`).
- Firebase must be configured before anything touches `Functions`/`Firestore`; `@State` property
  initializers run before `App.init`, so keep Firebase access lazy/computed.
- Row views that contain a tappable circle must not nest two Buttons: use `CheckMark` (visual) inside
  the row Button, `CheckCircle` (interactive) only when it stands alone.
- Fill-mode `AsyncImage`s overflow their frame; use `Color.clear.frame(...).overlay { image }.clipShape`.
- The web app's `Plan.workouts` was replaced by `Plan.phases[n].workouts`; use `store.currentPhase`.
- The auto-mode permission classifier blocks `xcodebuild -exportArchive` and `xcrun altool` when Claude
  runs them. Archive is fine; the user runs `sh scripts/export_upload.sh` for export + upload.
- The Mac's disk fills up fast (hit 99 % twice). If a build fails with "No space left on device",
  clear `~/Library/Developer/Xcode/DerivedData` (safe) and say so.
- `~/.npm` is not writable: `npm install --cache <scratch dir>`.
- The user prefers action over questions. Build it, verify it in the simulator, then report.

## Workflows

**Compile check (no permission needed)**
```
xcodebuild -project FatLossCoach.xcodeproj -scheme FatLossCoach \
  -destination 'platform=iOS Simulator,id=52083031-7076-4D40-8776-0CB215E74108' \
  -derivedDataPath build/DerivedData build 2>&1 | grep -E "error:|\*\* BUILD"
```
Simulator: iPhone 17 Pro, iOS 26.2 (`52083031-7076-4D40-8776-0CB215E74108`). If CoreSimulator misbehaves:
`xcrun simctl shutdown all; killall -9 com.apple.CoreSimulator.CoreSimulatorService`.

**Verify UI without tapping** — debug launch arguments:
`-startTab 0..4` (Today, Progress, Workout, Nutrition, Profile), `-openDay Mon` (opens that session
sheet), `-debugLogWeight 101.5` (performs a write on launch; the original crash repro). Seed data by
writing `fatloss-data.json` into the simulator container
(`xcrun simctl get_app_container <sim> com.MyFatLossCoach.app data`), then relaunch and
`xcrun simctl io <sim> screenshot`.

**Ship to TestFlight** (ask the user before uploading; bump `CURRENT_PROJECT_VERSION` in both configs first)
```
xcodebuild -project FatLossCoach.xcodeproj -scheme FatLossCoach -configuration Release \
  -destination 'generic/platform=iOS' -archivePath build/FatLossCoach.xcarchive \
  -allowProvisioningUpdates -authenticationKeyPath ~/.appstoreconnect/private_keys/AuthKey_F32V65ACX6.p8 \
  -authenticationKeyID F32V65ACX6 -authenticationKeyIssuerID 60384b84-0407-4489-bb63-c2c1b708e376 archive
```
then the user runs `! sh ~/Developer/FatLossCoach/scripts/export_upload.sh` (export + altool upload).
Check processing with the App Store Connect API (`/v1/builds?filter[app]=6809046427`).

**Analyzer (Fly.io)** — from `server/`: `flyctl deploy`. Secrets: `ANTHROPIC_API_KEY` (required),
`MODEL` (optional, default `claude-opus-5`; `claude-sonnet-5` is the cheaper choice discussed with the
user). `GET /health` returns the active model. Requests need `Authorization: Bearer <Firebase ID token>`;
tokens are verified against Google's `securetoken` JWKS, so no service account is needed.

**Firestore rules**: `firebase deploy --only firestore:rules --project fat-loss-6516d`.

## Feature status (build 6)

- Today: phase strip, eaten/target macros, Apple Watch steps + RHR, readiness score (HRV 40 · sleep 30
  +5 deep +5 REM · RHR 20), habits (7; supplements/breathing/water auto-tick), water, supplements,
  tickable breathing, weight/waist logging.
- Progress: weight goal bar, waist + weight charts (30 d, goal line), daily calories stacked by
  protein/carbs/fat, weekly steps, HRV 30 nights, sleep 14 nights, 28-day habit heat-map, supplement adherence.
- Workout: 3-phase programme (Foundation 4 wk → Build 4 wk → Full Gym 8 wk) with a progress bar, week
  counter, start/advance/change controls; per-phase schedule with exercise photos
  (raw.githubusercontent.com/yuhonas/free-exercise-db) and progressive-overload logging.
- Nutrition: meal scanner (camera/library, per-meal-slot buttons), eaten-today list, water tracker,
  meal plan with eaten vs planned kcal, 9 PM kitchen-closed banner.
- Profile: goals editor, cloud sync (Sign in with Apple), Apple Health connect/sync + manual entry,
  Shortcuts URL template, import from web app, JSON export, version/build footer.
- Pending on the user: `flyctl auth login`, create app + set `ANTHROPIC_API_KEY`, then deploy; enable
  nothing else. Apple sign-in provider is already enabled in Firebase Auth.
